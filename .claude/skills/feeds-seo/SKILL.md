# feeds-seo

The site is ~314 generated pages (one per ANVISA subfila) plus one Atom feed each, rebuilt daily.
Two audiences find it: people googling a subfila name or their own process number, and feed
readers that auto-detect a feed from an HTML URL. Every rule below serves one of those two.
For generic checks (headers, Lighthouse, hreflang) defer to the general `seo` skill.

## Site facts

- Base URL default: `https://anvisa.feeds.abelhaninja.de` (`cli.py`, `build` command,
  `--base-url`). The workflow passes no override.
- Everything under `site/` is generated by `build_site` in `feeds.py`; `site/` is gitignored.
  There is no static-assets directory. A new file means a new `write_text` in `build_site`.
- `page()` in `feeds.py` is the only HTML template. Head tags live there, not in callers.
- Pages are `lang="pt-BR"`; all visitor-facing copy is Portuguese.
- `meta["finished"]` (ISO 8601 with -03:00 offset) is the only truthful last-modified value.
  Never use build time or `date.today()` for lastmod/dateModified.
- `base_tag` (tag URI authority, `anvisa.feeds.abelhaninja.de,2026:feeds`) is for Atom ids
  only. Never put it in URLs, and do not change it again: readers re-show every entry when ids
  change.

## Invariants on every HTML page

- `<title>` is `{subfila} · {grupo} · {área}` on fila pages, "Filas de análise da ANVISA" on
  the index. Keep names first; they are the search keywords.
- `<meta name="description">`: one Portuguese sentence with name, queue count and date.
  Truncate the name if needed, never the numbers.
- `<link rel="canonical" href="{base_url}/…">`, absolute, no trailing slash on the base.
- Fila pages: `<link rel="alternate" type="application/atom+xml" title="…" href="…/fila/{id}.xml">`.
  This is what lets a reader subscribe from the HTML URL. The index links `feeds.opml` instead.
- Open Graph: `og:type`, `og:title`, `og:description`, `og:url`, `og:locale=pt_BR`,
  `og:site_name`, `twitter:card=summary`. No `og:image`; there is none, do not invent one.
- No `noindex`, no `nofollow`, no JavaScript needed to render content.
- All attribute values go through `html.escape(..., quote=True)`.

## Site-level files (all written by `build_site`)

| File | Rule |
|---|---|
| `sitemap.xml` | index + every `fila/{id}.html`; `lastmod` = `meta["finished"]`. Feeds (`.xml`) are not pages and are not listed. |
| `robots.txt` | `User-agent: *` / `Allow: /` / `Sitemap: {base_url}/sitemap.xml`. |
| `feeds.opml` | OPML 2.0, área → grupo → subfila outlines, `type="rss"`, `xmlUrl` and `htmlUrl` absolute. |
| `feed.xsl` | keeps feeds readable in a browser: explanation box plus entry titles as links. Never use `disable-output-escaping` (Firefox prints the tags as text). Do not remove the `xml-stylesheet` PI. |
| `fila/<id>.json` | the subfila's queue and the day's events as data; linked from the page's meta line, not in the sitemap. |
| notice | `build --notice "…"` renders a red `.box.warn` on every page; crawl.yml passes it when the crawl job failed. |
| index JSON-LD | one `Dataset` block; shape in `references/structured-data.md`. |
| fila JSON-LD | one `BreadcrumbList` (Filas › área › grupo › subfila); área/grupo items point at index anchors `#<area-slug>` and `#<area-slug>--<grupo-slug>`, which must exist. |

UI rules that also affect crawlers: the pages work with JavaScript off (the inline script only
reveals filter boxes and folds nothing that is not already in the HTML); the full queue is a
real `<table>`; position-change events fold into `<details>` above `FOLD_MOVED_ABOVE` but stay
in the markup. Do not add external assets, fonts or analytics.

## Content rules

- Keep the full current queue (process numbers, assunto, entrada) in the fila HTML. People
  google their own process number; that list is the long-tail asset.
- Index intro explains in Portuguese: what this is, how to subscribe (paste the `.xml` link or
  the page URL into Feedly, Inoreader, NetNewsWire, Thunderbird), how to find a processo
  (Ctrl+F on the page or filter in the reader), and that it does not replace the official
  consulta. Keep the provenance footer in `page()`.
- Do not add tracking scripts, cookie banners or external fonts. The site has none and ranks
  better without them.

## Audit procedure (read-only)

```bash
uv run anvisa-feeds build --snapshots snapshots --site "$TMPDIR/site"
ls "$TMPDIR/site"                     # index.html feed.xsl robots.txt sitemap.xml feeds.opml fila/
grep -c "<url>" "$TMPDIR/site/sitemap.xml"   # == feeds + 1
grep -o '<link rel="alternate"[^>]*>' "$TMPDIR/site/fila/167.html"
python -m http.server -d "$TMPDIR/site"      # open a fila page, view source
```

Then on the live site: `curl -s https://anvisa.feeds.abelhaninja.de/robots.txt`, paste the
index URL into https://validator.schema.org, paste a fila `.html` URL into a feed reader and
confirm it finds the feed. `uv run pytest` covers the sitemap, OPML, head tags and JSON-LD.

## Off-site checklist

- README links the site URL near the top. Repo About field has the URL; topics: `anvisa`,
  `regulatory-affairs`, `atom`, `rss`, `brasil`, `saude`, `github-pages`.
- `vasfvitor/anvisa-api` README and PyPI project URLs link back to the site.
- Search Console is deferred (decision 2026-10-09). To add later: a `--verification-meta`
  option on `build` emitting `<meta name="google-site-verification">`, read from a repo
  variable in `crawl.yml`; or a DNS TXT record on a custom domain.
- One well-placed post in a Brazilian regulatory-affairs community beats any on-page tweak.
